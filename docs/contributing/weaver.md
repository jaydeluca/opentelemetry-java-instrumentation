# Weaver Documentation Generation Guide

This project now includes Gradle tasks for generating documentation from weaver model files using
the OpenTelemetry Weaver tool. The model files are generated from collected telemetry
(`.telemetry/`) by the gradle task `./gradlew :instrumentation-docs:runAnalysis`, in the same
standard semantic-conventions registry schema (`manifest.yaml` + `groups:`-based YAML) used by the
hand-maintained `instrumentation/jmx-metrics/model/`.

The build system automatically finds all instrumentation modules with a `model/` directory and
creates Gradle tasks to generate documentation into a corresponding `docs/` directory.

## Model Directory Structure

Each instrumentation with weaver support will have:

```
instrumentation/<module-name>/
├── model/                          # Generated by `:instrumentation-docs:runAnalysis`
│   ├── manifest.yaml               # Registry metadata and the `otel` semconv dependency
│   └── <module-name>.yaml          # groups: metric/span/attribute_group definitions
└── docs/                           # Generated documentation goes here
    └── signals.md                  # Auto-generated
```

Attributes that already exist in the upstream semantic-conventions registry are emitted as
`ref:`; attributes specific to the instrumentation are defined locally in a `registry.<module>`
`attribute_group`. Telemetry only emitted under a non-default configuration is preserved rather
than dropped: an attribute added only under some configuration is marked
`requirement_level: {conditionally_required: ...}`, and a metric/span that only exists under some
configuration gets a `note:` describing the condition.

## Usage

### Generate Documentation for a Specific Module

```bash
./gradlew generateWeaverDocs-<module-name>

# Example:
./gradlew generateWeaverDocs-activej-http-6.0
```

### Generate Documentation for All Modules

```bash
./gradlew generateAllWeaverDocs
```

### List Available Documentation Tasks

```bash
./gradlew tasks --group=documentation
```

## Requirements

- Docker must be installed and running
- The otel/weaver docker image will be pulled automatically

## Output

Generated documentation will appear in:
- `instrumentation/<module-name>/docs/signals.md`

## Adding Weaver Support to a New Module

Model files are generated automatically for any module with collected telemetry
(`./gradlew :instrumentation:<module>:javaagent:test -PcollectMetadata=true` followed by
`./gradlew :instrumentation-docs:runAnalysis`), so a `model/` directory rarely needs to be
hand-written. To generate its documentation afterwards, run
`./gradlew generateWeaverDocs-<your-module-name>` — the build system automatically detects the new
`model/` directory and creates the task.
